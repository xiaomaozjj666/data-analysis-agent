一句话定位

先让评委记住这一句，再展开技术。

把 AI 写的经营数字，变成任何人都能独立复算、逐条验签、出错可追溯的简报。

不是「让 AI 写得更像人」，而是「让 AI 写的每个数字都必须过核验门」。产品把草稿拆成一条条可核对的主张，由本机核验器重新读原始 CSV 复算；只有复算一致、服务端重算并签章后才允许发布。评委拿到的不是一张截图，而是一个能自己跑的零信任证据包。

赛题特色功能

这不是普通的数据分析工具。可信 AI 赛题看的是「结论能不能被验证、责任能不能落到人」。

功能它解决什么现场一句话
服务端确认门客户端复算后，服务端按原始 CSV 再算一遍；audit_id 一致才允许写账本发布。「改过草稿再点发布，服务端会返回 409。」
范围门「华东区订单数」这类限定口径不会被确认开关放行。「确认的是全表口径，不是替你把范围也确认了。」
声明式核验口径每会话最多 12 项指标、每项 8 个过滤；支持 sum / count / count_distinct / min / max / mean / ratio、空值策略、舍入、正负策略、时间窗。「口径是声明出来的，不是让模型再写一段代码。」
哈希链账本 + Ed25519每次复算与确认追加一条记录，带 seq / prev / hash / 签名；只追加，改一个字节整条链对不上。「不是日志，是可以逐条验签的链。」
零信任证据包ZIP 自包含原始 CSV、草稿、口径、血缘、策略、账本、报告与公钥；评委用自己的 Python 从头复算。「你不需要相信我们的服务端，跑这个脚本就行。」
来源血缘登记上游表、抽取时间、负责人与新鲜度 SLA；超期告警；指纹写入账本。「数据从哪来、什么时候抽的、谁负责，都在包里。」
PII 脱敏与 RLS行级过滤与字段脱敏在聚合之前生效；预览不落原值；主体、策略指纹与过滤哈希入账。「没权限的行不会进指标，也不会出现在证据里。」
职责分离与版本历史口径作者不能自批，必须另一位同事批准；每次保存/批准都追加历史。「自己写的口径，自己批不了。」
AIGC 标识核验版简报末尾固定声明：草稿可由 AI 辅助起草、指标由核验器复算、发布前需人工确认。「哪些是 AI 写的，页面上写清楚。」
离线可跑复算、确认、账本、证据包不调用模型、不依赖外网。「断网也能把这条链走完。」

方式二：用现场自己的数据

  1. 上传：首页点「选择数据文件」，或把文件拖进工作区。支持 CSV、Excel、JSON、Parquet。
  2. 切到核验：上传解析后，点顶部「简报核验」页签。销售明细（含 order_id / sales / quantity）可直接用内置四项口径。
  3. 登记口径（非销售表必做）：在「核验口径」面板粘贴声明式 JSON，点「保存口径」，再点「按原表复算」。示例：
{
  "metrics": [
    {"name": "收入合计", "column": "revenue", "aggregation": "sum", "unit": "元", "decimals": 2},
    {"name": "订单数", "column": "order_id", "aggregation": "count_distinct", "unit": "笔"},
    {"name": "客单价", "aggregation": "ratio", "numerator": "收入合计", "denominator": "订单数", "unit": "元", "decimals": 2}
  ]
}

需要时可加 filters（eq / ne / gt / ge / lt / le / in / contains）、time_window、null_policy、rounding、sign_policy；一个会话最多 12 项指标。

访问策略：PII 与行级权限

展开「访问策略」面板，粘贴策略 JSON，点「保存访问策略」。过滤发生在聚合之前，预览里的 PII 列显示为「已脱敏」。

{
  "principal_id": "u_east",
  "claims": {"region": "华东"},
  "pii_columns": ["phone"],
  "rls": {"column": "region", "claim": "region"}
}

有策略但没有登记口径时，系统会回退内置销售四项；非销售表仍需要先登记口径。要清除策略，可调 DELETE /api/sessions/{id}/audit-policy，或在面板里把策略覆盖为空。

来源血缘（可选，加分项）

没有 UI 编辑面板，用一条命令写入 audit_lineage.json。上游表或 catalog URN 至少填一个，extracted_at 必须带时区。

$body = @{
  upstream_table = "dwd.orders_daily"
  extracted_at = "2026-11-21T08:00:00+08:00"
  owner = "data-platform"
  freshness_sla_hours = 24
} | ConvertTo-Json
Invoke-RestMethod "$base/api/sessions/$sid/audit-lineage" -Method Put `
  -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body))

草稿与快速起草

  • 路演视图点「改一个数试试」直接编辑草稿；草稿工作台的草稿框支持 Ctrl/Cmd + Enter 复算。

PPT 大纲

8 页足够。每页只回答一个问题，演示占第 3 页。

  1. 封面与痛点：「午会前收到一份 AI 写的简报，上面写着 462 笔订单。你敢直接用吗？」一句话定位放在副标题。右下角放产品名「有据经营简报」。
  2. 它怎么工作：草稿 → 核验器复算 → 服务端确认 → 证据包。四个环节各配一个短句；强调核验器只读原始 CSV，不调用第二个模型。
  3. 现场演示：462 → 20。21 条明细只对应 20 笔订单，差额 442。补一个范围门例子：「华东区订单数：8 笔」即使点「确认按全表复算」仍是 unsupported，因为统计范围被限定。
  4. 可信链：audit_id 由源文件哈希、草稿、确认标志与复算结果确定性生成；账本是只追加哈希链；每条记录带 Ed25519 签名。讲「改一个字节，整条链就对不上」。
  5. 零信任证据包：ZIP 里是原始 CSV、草稿、口径、血缘、账本、报告与公钥。评委用自己的 Python 跑 independent_replay.py，不 import 我们的代码。删签名、清空账本、替换口径，脚本一律退出 1。
  6. 安全与合规：PII 脱敏与行级权限在聚合之前生效；预览不落原值；主体、策略指纹与过滤哈希写入账本；核验版简报固定带 AIGC 标识；演示数据为合成数据。
  7. 公平与责任：口径作者不能自批，必须另一位同事批准；发布由具名主体确认；账本只追加，错误可更正但旧记录保留可查。
  8. 价值与边界：把「信 AI」变成「验 AI」，先用在经营简报、财报和成绩这类错一个数就要担责的场景。诚实边界一页：没有外部时间戳，不是不可否认基础设施；价值是让未经验证的输出无法直接发布。

90 秒逐字脚本

按钮名与当前 UI 一致。路演视图没有「核验口径」面板，需要时点「草稿工作台」。

约 90 秒 · 5 段
0–15 秒 · 开场

停在 462 笔的草稿上

首页点「体验简报核验」进入路演视图。问评委：「午会前收到这份简报，上面写着 462 笔订单。你敢直接把它当成订单量吗？」停两秒。需要讲口径时点「草稿工作台」，展开「核验口径」，说明默认是内置销售四项；讲完回到路演。

15–35 秒 · 复算与范围门

点「按原表复算」

现场揭晓 20 笔，指出多报的 442 笔。展开「查看来源」，指出前两行都属于订单 1001，所以 21 条明细只对应 20 笔。再点「改一个数试试」，点「插入范围门测试（华东区订单数）」并复算，指出它仍是 unsupported：统计范围被限定，不会被确认开关放行。市场份额缺少市场总量，留待人工复核。

35–55 秒 · 签章

点「签章并出具简报」

服务端按原始 CSV 重新复算，只有 audit_id 一致才写账本。页面出现「确认记录」：序号 #N、时间、hash 前 16 位，并写明「服务端按原始 CSV 重算后写入」。强调：客户端改过草稿，服务端会返回 409。

55–75 秒 · 哈希链与证据包

点「验签」，再下载证据包

点「验签」校验简报与回执一致；在完整核验页展开「查看哈希链账本」，指出每条记录的 seq / hash / prev 与 valid=true。点「下载证据包 (.zip)」，告诉评委：这个包可以带走，用自己的 Python 从头复算。

75–90 秒 · 改 1 个字节

用离线脚本收尾

用页面下载的简报跑 verify_audit_ledger.py --brief，先展示退出码 0；追加一个空格后再跑，展示退出码 1。强调源表未动，只改了导出文件的一个字节。最后交代边界：签名能发现内容被改，但没有外部时间戳，不是不可否认基础设施。

台词纪律：不要说「模型算得准」。说「模型可以算错，所以每个数字都要过核验门」。这句和产品定位一致，也不怕评委追问。

诚实边界

主动说边界，比被问住更可信。

  • 没有外部时间戳：Ed25519 能发现内容被改，但不能证明「谁在何时确认」之外的强不可否认性。
  • 公钥没有外部信任锚：证据包里的公钥与服务端同源；换公钥并重签不在演示级防护范围内。
  • 范围门不是通用语义核验：只覆盖已登记指标与已识别的范围写法，未登记口径进入 unsupported 或人工复核。
  • 快速起草是对照组：关闭思考、不调工具、只让模型读表心算；它的错误恰好证明核验门有必要，不代表产品分析能力。
  • Render 免费档会休眠：冷启动约 35–90 秒，现场以本机 run.bat 为主，Render 只作备用。

故障兜底

现场只处理三种故障，其余不要临时改代码。

浏览器停在令牌页

输入 .env 里的 APP_ACCESS_TOKEN，一次即可。run.ps1 启动时也会提示这一句。

模型不可用或超时

放弃「用模型直接起草」，改用已记录的草稿继续。核验、确认、账本与证据包都不经过模型。

端口被占用

run.ps1 会自动在 5173–5182 与 8000–8009 间找可用端口，并打印实际地址。以打印的地址为准。

现场被要求「给我证据包」

把 evidence/evidence-api_8cec7e1b455e.zip 给他，或页面点「下载证据包 (.zip)」。他用自己的 Python 跑脚本即可。

交接页基于 2026-11-21 本机实测：后端 1646 passed / 13 skipped，前端 24 文件 206 用例，证据包全链退出码 0。代码修复尚未提交；如果队友要从仓库拉代码，先确认提交状态。
