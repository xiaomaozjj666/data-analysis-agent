# 有据经营简报

2026 无锡可信 AI 挑战赛 · 03 进阶赛道「AI 应用创新挑战」

## 作品简介

运营团队把订单明细交给 AI 写经营简报时，销量、订单数和销售额的统计口径很容易混淆。有据经营简报将 [Data Analysis Agent](https://github.com/xiaomaozjj666/data-analysis-agent) 的报告起草能力与独立复算接在一起。用户导入订单 CSV，可以让 Agent 起草或直接粘贴待审简报。核验页回读原表，展示草稿原值、复算值、计算口径和源表记录。用户确认后导出核验版简报，证据不足或口径不清的内容留在核验明细中待复核。

## 启动和演示

在 Windows 双击仓库的 `run.bat`。首次启动会安装项目依赖，赛前提前跑一遍。已有依赖时，`简报核验` 的内置样例可全程在本机运行，无需模型 API Key。

1. 首页点「体验简报核验」进入路演。投影时可点「全屏」。先停在草稿的 462 笔，说明样例为合成数据，草稿含预设错误。
2. 点「复算并核验」，现场揭晓原表去重后的 20 笔。把 442 笔的差额和计算口径一起指给评委看。市场份额缺少市场总量，留待人工复核。
3. 展开「查看来源」，指出前两行都属于订单 1001，所以 21 条明细只对应 20 笔订单。来源卡也展示原表 SHA-256。有人问错误出在哪，点「草稿工作台」，再点冲突项的「定位第 3 行」。评委也可以改一个数字，由程序重新计算。
4. 点击「确认更正并生成简报」，下载 Markdown 和 `sales-audit.json`。明细保留草稿原文、判定、计算口径、数据来源和本次确认状态。讲完可点「重开演示」恢复开场。

已配置模型时，可从核验页点「准备 AI 起草任务」，在分析页生成并执行计划。报告生成后回到「简报核验」点「使用分析报告草稿」。会优先导入「待核验指标（全表）」小节。如果模型只返回普通报告，可将所需指标整理成下方格式后复算。现场可提前准备 AI 草稿，把路演时间留给复算和纠错。

本机一次实测中，DeepSeek 关闭深度思考后约 20 秒生成样例报告，三项指标经核验页全部通过。内置草稿可用于现场展示错数和无依据结论。

## 数据约定

- 上传 UTF-8 编码、逗号分隔的 CSV，包含 `order_id`、`sales`、`quantity` 三列。每行是订单明细，同一订单可包含多行。
- 全表统计。销售额按元输入、按分精确求和，销量为非负整数求和，订单数按 `order_id` 去重。缺少所需列或存在无效数据会提示修正源表。
- 草稿每行一个指标，单位为元、件、笔。数值使用半角数字，金额最多两位小数。重复指标、缺失单位和其他口径进入人工复核。草稿带标题或说明时，先确认保留的指标均描述原始 CSV 全表，再复算。

```text
销售额合计：17224.00 元
销量合计：462 件
订单数：20 笔
```

## 路演讲法

**解决的问题。** 运营团队可以复核 AI 起草的经营简报，避免把商品件数当成订单数。

**为何可信。** Agent 根据用户任务调工具形成草稿。核验器独立读取原始 CSV，按公开口径复算，并标出草稿行号、数据字段和原表 SHA-256。文件哈希用于定位那一版数据。

**如何纠错。** 对照 462 笔与 20 笔，跳到草稿第 3 行，再让用户确认更正。市场份额留待人工复核。演示中的修改发生在生成的简报里，源表始终作为证据，作品的现场操作止于本机预览和下载。

### 90 秒现场节奏

- **前 15 秒** 停在开场问：“午会前收到这份简报，上面写着 462 笔订单。你敢直接把它当成订单量吗？”
- **接着 40 秒** 点击复算，展示 20 笔和多报的 442 笔。展开原表，用一条记录和 `COUNT(DISTINCT order_id)` 讲清口径，再指一下待复核的市场份额。
- **最后 35 秒** 点击确认更正并下载。打开核验版简报给评委看，邀请他们到草稿工作台现场改一个数，观察结果如何变化。
